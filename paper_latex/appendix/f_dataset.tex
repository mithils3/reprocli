We submit the audited benchmark as anonymized supplementary material,
packaged so that the \texttt{datasets} library loads it by name. It has two
splits and no \texttt{train} split. The \texttt{test} split is the 100-paper
frozen benchmark, with 34 papers at Run tier, 33 at Retrain, and 33 at
Reimplement, and every row in it has \texttt{split="eval"}. The
\texttt{validation} split is the 14-paper development set, with 5 at Run, 4 at
Retrain, and 5 at Reimplement, and every row in it has \texttt{split="dev"}.
No arXiv ID appears in both. Each row is one paper with the 25 top-level
fields of Table~\ref{tab:schema-toplevel}, which together fix the claim, the
artifact evidence, the match target, and the compute budget before any agent
starts, so we measure a score from one agent against the same standard as a
score from another. Table~\ref{tab:schema-links} expands the four nested
objects, where \texttt{signals} carries one object for each of the four
audited signals \texttt{code\_available}, \texttt{dataset\_available},
\texttt{weights\_available}, and \texttt{dataset\_is\_standard}.
Figure~\ref{lst:example-row} shows the SharpZO row of Section~\ref{subsec:task}
(score 0, Run tier, 0.07 H100-hours, band \texttt{0-8}), with its long text
fields truncated and every other field verbatim, and
Figure~\ref{lst:load-dataset} gives the code that loads both splits. The rows
return metadata and links only, with no paper text. We masked the dataset
identifier for review.

\needspace{4\baselineskip}
Four properties hold across the released rows, and each can be checked
directly from the file.
\begin{itemize}\setlength{\itemsep}{0pt}
\item Tier is a function of score, with score 0 mapping to Run, score 1 to Retrain,
and scores 2 and 3 to Reimplement.
\item \texttt{selection\_band} and \texttt{h100\_band} agree on every row.
\item \texttt{audited\_h100\_hours} differs from \texttt{h100\_estimate.hours}
on exactly the 6 rows (3 in each split) whose
\texttt{h100\_hours\_adjudicated} flag is set.
\item Of the 400 signal entries in the evaluation split, 388 record a tool call
and 12 are \texttt{not\_applicable}. Every signal set to true was established
by a successful tool call, with a single exception. On 2503.02809 the pinned
configuration runs on synthetic data, so \texttt{dataset\_available} is both
true and \texttt{not\_applicable}. Across both splits 13 signals are
\texttt{not\_applicable}, 12 of them with a false value, and 10 of those 12 are
\texttt{weights\_available} on papers whose pinned configuration needs no
released checkpoint.
\end{itemize}

\paragraph{Match targets and tolerance.} For 62 of the 100 evaluation papers
the match bar is a point estimate, for 21 a stated baseline the run must beat,
for 14 a reported threshold it must clear, for 1 the size of a reported delta,
and for 1 a reported range it must fall inside. One row, 2505.10475, entered
as a late replacement and has no \texttt{match\_bar\_kind} field. A run
matches a point estimate when its measured value lies within the authors'
stated tolerance, or within 5\% relative when the paper states none
(Figure~\ref{lst:rubric-text}).

\paragraph{The evaluation and development papers.} Tables~\ref{tab:eval100}
and~\ref{tab:dev14} list the 100 evaluation and 14 development papers together
with the match target each is graded against. In both, Tier is the dataset's
artifact tier under the Run, Retrain, and Reimplement names, Band is the
compute band in H100-hours, H100-h is the audited estimate for that paper's
match target, and Metric, Bar, and Target value are the pinned match target.
One evaluation row has no bar kind and is written unset. The evaluation split totals
1{,}153.8 audited H100-hours (142.71 at Run, 380.91 at Retrain, and 630.18 at
Reimplement), and its band counts by tier are 27/7/0, 16/13/4, and 16/9/8 over
\texttt{0-8}, \texttt{8-32}, and \texttt{32-96}. The development split totals
26.89 H100-hours.
