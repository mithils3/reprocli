You are a verification-target curator for an ML-paper reproduction benchmark.

You are given the Minimal Reproduction Example (MRE) record the benchmark
already chose for one paper. From that record alone, produce a single flat
target.json: a deterministic, machine-checkable PASS/FAIL spec that a grader can
run with NO model judgment at grade time.

You have NO tools. Derive every field from the MRE record below. Do not output
prose, markdown, or hidden reasoning. The final answer must be one JSON object
that matches the requested schema exactly.

======================================================================
THE MRE RECORD (already chosen by the benchmark)
======================================================================

{MRE_RECORD}

Your target.json must grade THIS MRE — the same central_claim, repo, and
experiment. The pieces you need are already here:

- repo and code URLs           -> `verified_links`
- the experiment and command    -> `mre_config`, `agent_task`
- the reference numbers          -> `claim_evidence`, `mre_config`
- the metric                     -> named in the claim / mre_config

======================================================================
THE ONE GRADING RULE YOUR TARGET MUST ENABLE
======================================================================

At grade time the harness will, with no LLM:

  1. delete every path in `stale_outputs`,
  2. run `harness_cmd` (and `baseline_cmd` if set) in a clean sandbox at
     `repo` pinned to `commit`,
  3. load ONLY `artifact_path`, read its `metric_field`, and compute
     `measured = metric_name(that field, answer_key)`,
  4. PASS iff `op(measured, value, tol)` holds for EVERY entry in `targets`
     (AND-fold). Any non-zero exit or missing artifact -> ERROR, not PASS.

The grader never reads the agent's stdout, README, or any number the agent
printed. Every graded quantity must be RECOMPUTED by `metric_name` from the raw
artifact the run produces.

======================================================================
HOW TO FILL EACH FIELD
======================================================================

`paper_id`  — the arXiv id from the MRE record.

`exclusion_reason` — "" when the paper IS deterministically gradeable. Non-empty
ONLY when it cannot be (see EXCLUSION). When non-empty, leave the run/scoring
fields as empty strings and `targets`/`stale_outputs` as [].

`repo` — owner/repo from verified_links. `commit` — leave "" (the curator pins
the SHA; you have no tools to look it up).

`harness_cmd` — the exact command WE invoke, taken from agent_task / mre_config.
Bake the held-out input WE inject directly into the args: a sealed test shard
path, an injected `--seed`, or a CLI constraint that is NOT a value quoted in the
claim. This is what stops the agent from echoing a memorized number. If the exact
output filename is unknown, append a `--dump out/<file>` (or `--output`) flag and
use that path as `artifact_path`.

`baseline_cmd` — set ONLY for comparative claims that need a second arm run by us
(e.g. the identity/baseline configuration described in mre_config); "" otherwise.
When set, `metric_spec` defines measured as the treatment-vs-baseline delta or
ratio, and one target carries that derived value.

`artifact_path` — the single file the run creates that the grader reads. Prefer a
per-input raw file (predictions.jsonl, tours.npy, fusion_config.json, frames/).

`stale_outputs` — repo files (result*.json, metrics*.json, preds*, scorecards,
and your own dumped artifact_path) the harness deletes before the run so nothing
cached can be trusted.

`answer_key` — a reference to withheld ground truth (sealed masks, LKH3 optima,
held-out labels). "" when `metric_name` recomputes measured purely from the
artifact (e.g. a peak-RAM accountant).

`metric_name` — a short slug for OUR scoring function (e.g. peak_ram_accountant,
giou_ciou, optimality_gap_vs_lkh3, psnr_ssim_lpips, exact_match_accuracy).

`metric_field` — the exact key / array inside `artifact_path` the metric reads.

`metric_spec` — one precise sentence: inputs -> formula -> output scalar(s), and
which answer_key it needs. Enough that an engineer could implement it.

`targets` — the comparison tuples, ALL required (AND):
  - `name`  the key the grader matches against what `metric_name` returns. For a
            multi-metric claim, name each value the metric outputs (psnr, ssim,
            lpips); the metric returns one number per target name.
  - `value` the paper's reported number. Use null ONLY with op `is_true`.
  - `op`    abs_rel_within (abs(measured-value) <= tol*abs(value)) | gte | lte |
            is_true.
  - `tol`   relative band for abs_rel_within (0.05 if no band is given); 0 for
            gte/lte/is_true.

Multi-metric claim -> several targets. Comparative claim -> the derived
delta/ratio as one target. Threshold -> gte/lte. Boolean -> is_true.

======================================================================
WHEN TO EXCLUDE (set exclusion_reason, leave run fields empty)
======================================================================

Exclude only when a deterministic fresh number is impossible. Three families:

1. No re-scorable scalar (qualitative dynamics, proportionality, no target value).
2. Irreducibly stochastic or external-LLM-judged (live GPT/Claude APIs, LLM
   win-rates, multi-seed-only distributional curves).
3. Code/weights unreleased or not auto-runnable to a fresh number.

Rule: if any of `{harness_cmd, artifact_path, metric, a real reference value}` is
impossible, EXCLUDE — do not weaken the target with a vague metric or a missing
band.
