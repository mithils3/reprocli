\subsection{Grading procedure}

% src: rubric_audit.md:17-31; prompts/prompt_audit.txt:1-9,5-9,54-58,138-139; src/reclaim_vllm/audit/inputs.py:1-9; src/reclaim_vllm/audit/audit.py:1-12
Each audit grades a single agent's attempt at a single paper's central claim.
The auditor receives the claim with its pinned match target, a manifest of the
agent's run bundle, and the frozen rubric text of Figure~\ref{lst:rubric-text},
and it explores the bundle with the tools of Table~\ref{tab:audit-tools}, which
both graders receive under the same limits. Every path argument is resolved
against the run directory, and the tools reject absolute paths, backslashes,
and parent references, so a grade can only cite the bundle under audit. It assigns one integer from 0 to 10,
first placing the run in the highest quality band whose conditions the cited
evidence meets, then applying an integrity adjustment that can only lower the
score. The rubric sets a low-score prior, so a run with no evidence scores
low, and the auditor does not treat a printed number as verified. It treats
the agent's own report as a set of claims to be verified against the files it
cites. The auditor returns no verdict string. The verdict is derived from its
row in code (Appendix~\ref{app:rubric-finalizer}).

% src: rubric_audit.md:33-43,35-85,87-91,93-97,99-127,150-164
The auditor works through six criteria, citing bundle evidence for each. C1
fixes the target from the pinned tuple in the dataset row, choosing only the
comparison operator and tolerance appropriate to the pinned bar kind. C2
verifies that the agent ran code that computed the metric, and checks
the executed dataset, split, checkpoint, and model size against the pinned
scope. C3 locates the measured value and cites the file and line it came from,
and C4 tests the number's provenance. C5 applies the C1 criterion to the
measured and reference pair, and C6 checks that the run reproduced the
experiment the claim rests on. For a relational claim, every check is applied
to the baseline side with the same rigor. Two of the six criteria can end the
grade, since a claim with no checkable target and a number with no execution
trace both score 0.

% src: rubric_audit.md:99-148; prompts/prompt_audit.txt:86-105; src/reclaim_vllm/schema/audit.py:29-39
Each provenance break that C4 finds is recorded as a typed flag with cited
evidence and one of three severities, and any high-severity flag caps the
score at 0. The rubric holds the graded quantity to a stricter standard than
the inputs. Released weights, datasets, splits, configs, and code are inputs
the agent is expected to consume, whereas the graded quantity must have been
computed in this run from model outputs this run produced. A value the agent reads from a
shipped results file and discloses as such therefore caps the band at 4
without raising a flag. The same value placed in the target slot as this run's
own measurement is fabricated provenance.

% src: src/reclaim_vllm/schema/audit.py:66-125,90-94; src/reclaim_claude/agent.py:155-178; rubric_audit.md:238-246; prompts/prompt_audit.txt:135-139
Alongside the score, the auditor returns a confidence and a one-paragraph
rationale. Whenever confidence falls below 0.6, or a judgment call shaped the
score, the rationale must say what a human spot-check should examine and which
file to open.

\subsection{Score scale and verdicts}

% src: rubric_audit.md:166-171,224-236; src/reclaim_vllm/audit/audit.py:74-90
Table~\ref{tab:rubric} lists the quality bands and the verdict derived from
each score, where a score of 1 yields \texttt{unverifiable} when the auditor
also reports that execution was not verified. We froze the rubric text on 2026-07-16, three days after the
dataset freeze, and every pinned-auditor grade reported in this paper
postdates that freeze (Appendix~\ref{app:auditor-validation}).

% src: rubric_audit.md:3-15,204-209,228-232
No band gives credit for a claimed artifact wall, that is, an agent's report
that a required artifact could not be obtained. During curation we removed
every paper with an observed hard wall and host-probed the rest, so each
remaining artifact was verified retrievable from the run host
(Appendix~\ref{app:construction}). A claimed wall is therefore graded on what
the run achieved, and the auditor writes a curation escalation into
\texttt{methodology\_notes} for human review.

\subsection{Auditor prompt and tools}

% src: prompts/prompt_audit.txt:35-58,79-84; src/reclaim_vllm/tools/run_dir_tools.py:1-19,274-288; src/reclaim_vllm/config/config.py:50-54
Where recomputation is inexpensive, the auditor recomputes metrics from the
stored predictions and outputs, and the 60\,s shell timeout rules out
re-running training or evaluation. Figure~\ref{lst:audit-prompt} shows the
prompt template, which is rendered for each graded run from the pinned claim,
the run-directory manifest, and the rubric text. We ran the sweeps under a
development name, and the released file carries the public name RECLAIM in
that one line.
