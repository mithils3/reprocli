\section{Model and Serving Details}
\label{app:models}

% dates: repro_runs started_at/finished_at of the three muse_spark batches
We serve the three open-weight agent models on our cluster with vLLM, each from
a per-model profile the launcher expands into one \texttt{vllm serve} command,
and a sweep is one batch job per model per tier that launches the server and
runs that tier's papers as processes on the same node. Each \texttt{run\_gpu}
call takes its own Slurm allocation (Appendix~\ref{app:harness}), so agent
compute is metered apart from the serving GPUs, and the advertised model ID is
recorded on the run row. Muse Spark 1.2 is reached through the Meta Model API
between 2026-08-14 and 2026-08-23, its sweeps run as a login-node process with
no job wall clock, and since the API advertises no context length we declare
1{,}000{,}000 tokens. Table~\ref{tab:models} lists the four configurations.
For the three vLLM-served models the launch script takes precedence over the
profile where they disagree, and ``not set'' means the server or checkpoint
supplies the value. The agent input ceiling is the served context less the
32{,}768-token completion reservation, the \texttt{top\_p} of $0.95$ follows
the DeepSeek-V4-Flash card's agentic
recommendation~\citep{deepseekai2026flashcard}, and concurrent papers, the
number of papers a job runs at once, is listed for the Run, Retrain, and
Reimplement tiers in that order.

Four caveats qualify comparisons across models. Reasoning effort is held
constant within the three DeepSeek-V4-Flash sweeps and within the three Muse
Spark 1.2 sweeps, at different settings, and the Qwen3.6-27B and MiniMax-M2.7
launch scripts set none, so effort is uncontrolled across models. Precision
differs by model, and MiniMax-M2.7 is a third-party W4A16
requantization~\citep{lin2023awq}, lossy by construction, served under the
upstream name with no correction. Served context differs, so the agent input
ceiling differs, from 163{,}840 tokens to 967{,}232, and a run that exhausts
its context on one model would have had more room on another. Muse Spark 1.2 runs on the vendor's servers, so
its precision, batching, and decoding defaults are unrecorded, and we fix only
the reasoning effort and the round budget. Separately, we disable two
compilation fusions for DeepSeek-V4-Flash because we observed them garbling this
checkpoint's decoding on this hardware.

We produce the grades of record with a separate grading client on the
Anthropic Messages API with \texttt{claude-sonnet-5}, one agent loop over one
run bundle capped at 25 rounds, and re-grading a batch overwrites its audit, so
a re-graded sweep has one grader. We price GPU time at the \$2
per H100-hour of Section~\ref{subsec:experimental-setup} and grader tokens at
\$2 and \$10 per million input and output tokens~\citep{anthropic2026pricing}.

\paragraph{Token usage and cost.} Each rate comes from that vendor's own
endpoint listing on 2026-08-17, with cached prompt tokens billed at the
cache-read rate where one is listed, and Table~\ref{tab:cost} covers the 396
runs that started, the 372 graded runs and the 24 runs of
Appendix~\ref{app:missing-cells} with token counts, plus the GPU time each
agent drew from its grant. Three things qualify the total. The token dollars
of the three cluster-served models are what a rerun against the vendor
endpoint would cost, and our serving GPUs' hours sit outside the table. The
MiniMax-M2.7 rate is the upstream model's while we served the requantization
of Table~\ref{tab:models}. Our Qwen3.6-27B deployment returned no cached-token
counts, and its vendor lists no cache-read rate, so all its prompt tokens are
priced at the full rate. The audit records retain no grader
token counts.

\subsection{Cells without a graded run}
\label{app:missing-cells}

% numbers of record: repro_runs + audit_runs (Supabase, read 2026-09-10) joined
% to the HF eval_100 tiers and tools/anon_viewer/public/data/index.json; the
% renderer defect reproduced locally with `python -m reclaim_repro --paper-id
% 2510.20725` (ValueError: unfilled placeholders: {O}) and fixed the same day;
% the three late runs carry two pinned Sonnet passes each. Policy (2026-09-10):
% every cell without a graded run counts as a failure; the text states what each
% cell holds and gives no cause for the 19 runs without a final report.
Four agents over 100 papers give 400 cells, 372 of which hold a run with a
pinned grade and a failure-mode label. Table~\ref{tab:missing-cells} lists the
other 28, all counted as failures in Section~\ref{subsec:results} and
Table~\ref{tab:results}, at score 0 or at the pinned grade, 0, 2, and 0, for
the three that hold one, and outside the failure-mode counts of
Section~\ref{subsec:mechanisms}. In 19 cells the run ended without a final
report, so the auditor had nothing to grade. The 4 cells with no run share one
Retrain
paper whose target contains the characters \texttt{\{O\}}, which the
placeholder-filling routine (Appendix~\ref{app:prompts}) rejected as an
incomplete prompt, a check we have since corrected; the 3 cells with a grade
and no label were graded after we had labeled their sweep, and in the 2 cells
with a run and no pinned grade the auditor's pass started and returned no
verdict. The 24 runs
that started are in the compute and cost figures and spent 118 of the
1{,}888 H100-hours of Section~\ref{subsec:compute}.
