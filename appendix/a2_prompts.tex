Figure~\ref{lst:harness-messages} in Appendix~\ref{app:prompt-listings}
collects every fixed string the model reads during an episode. The system message is stored at index 0, where compaction
never reaches it. The final-turn instruction is appended after the harness
removes the tools and constrains the response to the report schema of
Appendix~\ref{app:report-format}. The harness inserts five further strings
during an episode, namely the status line appended each round, the budget
note, the length nudge after a turn hits the output cap, the elision
placeholder that compaction leaves behind, and the tool-error fields. The task prompt, which
follows the system message as the first user turn, is shown in
Figure~\ref{lst:task-prompt} of the same appendix.

The task prompt is a single 290-line template with fourteen placeholder fields
under nine headings. Each field is filled from the paper's dataset row
(Appendix~\ref{app:dataset-schema}), from the episode's compute ceiling, or
from the fixed container paths of Appendix~\ref{app:sandbox}. Rendering fails
with an error if any field is left unfilled, and every field has a fallback
string, so the renderer writes an explicit statement of absence where a row
lacks a value. The renderer omits \texttt{match\_target.config}, the runnable
configuration that produces the target value, so the agent has to derive that
configuration from the paper.

We revised the template from transcript dissections of earlier agent runs,
and checked each revision against other models' successful runs before
adopting it. In a cross-model audit on 2026-06-28 we removed two rules that
were specific to one model's behavior, a push toward requesting more GPUs and
a budget-fraction test for under-running. The template has not changed since 2026-07-11, and
Figure~\ref{lst:task-prompt} in Appendix~\ref{app:prompt-listings} reproduces it in full.
