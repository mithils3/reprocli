# ReproBench Paper Selection Methodology

## Goal

Select about 400 NeurIPS 2025 papers for ReproBench so the benchmark measures
two different things cleanly:

1. How agent success changes with artifact availability.
2. How agent success changes with compute budget inside each artifact tier.

The benchmark should not simply be "the easiest 400 recent papers." It should be
a stratified benchmark where the four evaluated difficulty tiers are equally
represented, while keeping each selected reproduction target cheap enough to run
on DeltaAI.

## Inputs

Use the existing repo artifacts as the source of truth:

- `prompt.txt`: artifact-availability prompt that assigns the MRE tier and
  estimates H100-hours.
- `notes/reprobench_memo.pdf`: project memo defining the ReproBench objective,
  the minimum reproducible claim, and the 250-500 paper target.
- NeurIPS 2025 arXiv-backed corpus generated by the local fetch/download tools.
- Model output JSONL files, after JSON parsing and human audit.

The prompt's core principle should stay fixed: the tier is based on artifact
availability, not absolute compute cost. H100-hours are a separate axis.

## Tier Definitions

Use four evaluated tiers plus one logged-only exclusion bucket.

| Selection tier | Prompt tier | Practical meaning |
| --- | --- | --- |
| Tier 1 | Easy | Code, data, and MRE weights are available; usually eval-only or light rerun. |
| Tier 2 | Medium | Code path exists, but weights or some reconstruction/retraining is needed. |
| Tier 3 | Hard | Substantial missing artifact, often missing code or weights. |
| Tier 4 | Hardest | Paper-only or near-paper-only reproduction from the MRE description. |
| Tier 5 | Out of scope | Proprietary data, impossible access, or compute beyond the benchmark cap. |

Tier 5 papers should be kept in the corpus metadata for transparency, but not
included in the main 400-paper evaluation set.

## Recommended Split

Use a balanced 400-paper benchmark:

| Tier | Target count |
| --- | ---: |
| Tier 1 / Easy | 100 |
| Tier 2 / Medium | 100 |
| Tier 3 / Hard | 100 |
| Tier 4 / Hardest | 100 |

This is the right default because the central result is a compute-versus-score
curve by difficulty tier. Equal tier sizes make those curves easier to compare
and keep the benchmark from being dominated by whichever artifact pattern is most
common in NeurIPS 2025.

If one tier has fewer than 100 valid in-scope papers after audit, fill the
remaining slots using a documented rule:

1. First, take all valid papers from the scarce tier.
2. Then distribute the deficit equally to neighboring tiers by artifact
   difficulty.
3. Record both the intended and actual tier counts in the release metadata.

## Why Not Just Pick the Lowest 400 H100-Hour Papers?

Selecting the global lowest-H100 papers would make the benchmark cheaper, but it
would bias the dataset toward eval-only, small-model, standard-benchmark papers.
That would undercut the main scientific question: where do reproduction agents
fail as artifacts disappear?

The better rule is:

1. Stratify by tier first.
2. Select low-H100 papers within each tier second.
3. Apply diversity and audit guardrails before locking the final set.

This keeps cost under control without collapsing the benchmark into one corner
of the reproducibility landscape.

## Candidate Filtering

Before tier sampling, remove papers that fail hard eligibility checks.

A paper is eligible only if:

- The paper text and enough supplementary/project text are available to define
  a concrete MRE.
- The central empirical claim can be tied to a specific table, figure, or metric.
- The MRE can be expressed as a non-interactive `reprocli` task.
- Required data are public, standard, or legally obtainable by the benchmark
  runner.
- The estimated MRE compute is below the current benchmark cap.

Default compute cap:

- Main benchmark: at most 128 H100-hours for the selected MRE.
- Stretch pool: 128-512 H100-hours, kept as optional future targets.
- Out of scope: over 512 H100-hours, proprietary data, or access-gated artifacts
  that cannot be obtained reproducibly.

The cap should apply to the MRE, not the largest experiment in the paper.

## H100-Hour Selection Rule

Within each tier, sort papers by audited `h100_hours_estimate` ascending, but do
not blindly take the first 100. Use a low-compute-biased stratified rule:

| Compute band | Per-tier target |
| --- | ---: |
| 0-2 H100-hours | 20 |
| 2-8 H100-hours | 25 |
| 8-32 H100-hours | 30 |
| 32-128 H100-hours | 25 |

This still favors cheaper papers, but it preserves enough compute spread to make
the 2, 8, 32, and 128 GH200-hour agent-budget sweep meaningful.

If a tier does not have enough papers in a band, refill from the next cheapest
band in the same tier. Do not refill from another tier unless the whole tier is
short after audit.

## Diversity Guardrails

After low-H100 ranking, apply light diversity constraints so the set is not 400
versions of the same task.

Recommended soft caps per tier:

- No more than 35% from one broad area such as LLM fine-tuning, diffusion,
  vision-language, robotics, systems, theory-with-experiments, or bio/chem ML.
- No more than 25% using the same primary benchmark family.
- No more than 20% relying on the same base model family, unless that tier would
  otherwise be underfilled.
- Prefer papers with clear MRE anchor metrics over papers whose main claim is
  qualitative or hard to score.

These caps are soft because reproducibility difficulty is the primary axis. Any
exception should be recorded in the selection metadata.

## Audit Procedure

The model can propose tiers and H100 estimates, but the final benchmark needs a
human-audited lockfile.

For every candidate selected into the 400-paper set, audit:

1. MRE claim: one-sentence central claim plus table/figure evidence.
2. MRE config: smallest model/dataset/protocol that still tests the claim.
3. Artifact signals: code, dataset, weights, and whether the dataset is standard.
4. Tier arithmetic: score and tier match the prompt's deterministic mapping.
5. H100 arithmetic: GPU count, wall time, GPU type, and conversion are coherent.
6. Access status: links still resolve and are public at lock time.
7. Agent task: the task is concrete enough for `reprocli replicate`.

Flag common failure modes:

- Confusing a released benchmark repo with released method code.
- Counting "code will be released" as available.
- Counting non-MRE weights as MRE weights.
- Treating a custom released dataset as a standard benchmark.
- Converting GPU-days into H100-hours incorrectly.
- Estimating compute for the flagship model instead of the cheapest valid MRE.

## Selection Algorithm

1. Run the artifact classifier over the NeurIPS 2025 arXiv-backed corpus.
2. Parse JSON outputs and reject malformed or non-JSON answers for rerun.
3. Normalize tiers to Tier 1-4 plus Tier 5/out-of-scope.
4. Apply eligibility filters and compute caps.
5. Human-audit a candidate pool larger than needed, ideally 150 per tier.
6. Within each tier, bucket audited candidates by H100-hour band.
7. Fill the per-tier quotas using lowest-H100 papers inside each band.
8. Apply diversity guardrails and replace outliers with the next audited
   candidate from the same tier and compute band.
9. Freeze a benchmark lockfile with paper ID, title, tier, MRE, anchor metric,
   tolerance, H100 estimate, verified artifact links, and selection rationale.
10. Keep a reserve list of at least 25 alternates per tier.

## What To Release

Release three benchmark files:

- `reprobench_candidates.jsonl`: all classified in-scope and out-of-scope papers.
- `reprobench_selected_400.jsonl`: the locked main benchmark.
- `reprobench_reserve.jsonl`: audited alternates, ordered by replacement priority.

Each selected row should include:

- `paper_id`
- `title`
- `neurips_url`
- `arxiv_id`
- `tier`
- `score`
- `central_claim`
- `claim_evidence`
- `mre_config`
- `anchor_metric`
- `tolerance`
- `agent_task`
- `h100_hours_estimate`
- `h100_estimate_basis`
- `verified_links`
- `selection_band`
- `selection_rationale`
- `audit_status`

## Final Recommendation

Use the equal 100/100/100/100 tier split as the benchmark spine. Within each
tier, prefer the lowest audited H100-hour papers, but sample across the four
compute bands instead of taking a pure cheapest-first list. This gives the
project a benchmark that is affordable, tier-balanced, and still informative for
the compute-versus-reproduction-success curves that ReproBench is meant to
measure.
